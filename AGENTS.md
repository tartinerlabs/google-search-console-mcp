# AGENTS.md

This file provides guidance to AI coding agents when working with code in this repository.

## Commands

pnpm only (`pnpm-lock.yaml`, pnpm 12 and Node declared in `devEngines`). pnpm workspace: the Google Search Console server lives in `apps/gsc`, and Biome and semantic-release run from the root. Paths below are relative to `apps/gsc` unless noted.

```sh
pnpm check                          # root: biome lint + typecheck + vitest in every app — what CI runs, plus `pnpm build`
pnpm test                           # root: vitest run in every app
pnpm format                         # root: biome format --write
pnpm build                          # root: tsc -p tsconfig.build.json → apps/*/dist/
pnpm -C apps/gsc vitest run tests/tools.test.ts      # single file
pnpm -C apps/gsc vitest run -t "search_analytics"    # single describe/test by name
pnpm -C apps/gsc db:push            # sync schema to the Neon development branch
pnpm -C apps/gsc db:migrate         # apply committed migrations (also runs as `vercel-build`)
```

Tests need no database, network or Google credentials: they drive `createServer` with a mocked `GscClient` (`tests/helpers.ts` → `mockClient`, `mcpRequest`, `createTestClient`) and never import `src/lib/auth.ts`.

## Architecture

A stateless Streamable HTTP MCP server for read-only Google Search Console access, deployed to Vercel as a single Hono function (`vercel.ts`: `framework: "hono"`, region `sin1`). TypeScript runs as native ESM with `.ts` import extensions (`rewriteRelativeImportExtensions`, `erasableSyntaxOnly` — no enums/namespaces/parameter properties).

Request flow:

1. `src/index.ts` — Hono app routing `/api/auth/*` and `/.well-known/*` to Better Auth, `POST /mcp` to `handleMcp`, and `/sign-in` + `/consent` to `src/pages.ts`.
2. `src/http.ts` — Host/Origin validation (`MCP_ALLOWED_HOSTS`, `MCP_ALLOWED_ORIGINS`, Vercel system URLs), then `requireMcpAuth` from `@better-auth/mcp` verifies the JWT access token and maps claims to `AuthInfo` with `extra.userId = sub`, then `createMcpHandler` builds a fresh `McpServer` per request.
3. `src/server.ts` — `createServer(getClient)` registers `ping` plus one tool per file in `src/tools/`. Each `register*Tool(server, getClient)` takes a lazy `GscClientProvider` so credentials are resolved inside the tool call and auth failures surface as tool errors, not HTTP errors.
4. `src/google/client.ts` — `getUserGscClient(userId)` loads the user's Google account via Better Auth's internal adapter, checks the `webmasters.readonly` scope was actually granted, gets/refreshes the Google access token via `auth.api.getAccessToken`, and wraps `@googleapis/searchconsole` behind the narrow `GscClient` interface (the seam tests mock).

Auth (`src/lib/auth.ts`): Better Auth is the OAuth 2.1 authorisation server for MCP clients — Google as the only social provider (offline access, encrypted tokens), JWT plugin, `mcp` plugin (resource = `${BETTER_AUTH_URL}/mcp`), and CIMD (client ID metadata documents; dynamic client registration is off). `/sign-in` and `/consent` in `src/pages.ts` verify Better Auth's signed query and render minimal HTML with strict CSP.

Tool conventions (follow when adding a tool):
- Zod 4 input schemas (`import * as z from "zod"`); shared ones such as `siteUrlSchema` live in `src/schemas/common.ts`.
- Annotate `readOnlyHint: true`; `tests/server.test.ts` asserts the exact tool list and that every tool is read-only.
- Return JSON as a text content block; wrap the body in `try/catch` and return `toToolError(toolName, error)`. `src/utils/errors.ts` classifies Google/Gaxios/network errors into `[invalid_input|auth|permission|quota|not_found|unavailable|network|unexpected]` messages. Throw `CredentialsError` for sign-in problems.
- Log only through `src/utils/logger.ts` (Pino with redaction of tokens/secrets/headers); never log tokens or put them in tool results.

## Database

Drizzle ORM 1.0 RC on Neon Postgres (`src/db/index.ts`, node-postgres, relations v2). `drizzle.config.ts` uses `DATABASE_URL_UNPOOLED` and `schemaFilter: ["public"]` (Neon Auth owns `neon_auth`).

- `src/db/schema/auth.ts` is generated by the Better Auth CLI (`pnpm auth:generate`, needs `BETTER_AUTH_URL`) and `drizzle/` is generated by Drizzle Kit. Never hand-edit either; both are excluded from Biome.
- Neon `development` branch: iterate with `pnpm db:push`. `production` branch: schema changes only via committed migrations. Do not run `pnpm db:generate` unless explicitly asked.

## Environment

Required: `DATABASE_URL`, `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL` (must exactly match the URL clients use for `/mcp`), `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`. Optional: `MCP_ALLOWED_HOSTS`, `MCP_ALLOWED_ORIGINS`, `LOG_LEVEL`. See README for Google Cloud and Vercel setup. Vercel Deployment Protection blocks the self-hosted JWKS fetch and OAuth flow on preview deployments.
